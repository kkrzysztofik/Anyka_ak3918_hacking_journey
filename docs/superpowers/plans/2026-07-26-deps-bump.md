# Dependency Bump (App + Validation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump Rust and Node dependencies for the cross-compile workspace, validation tool, and WebUI to the newest published versions (including majors), then fix breakage so quality gates pass.

**Architecture:** Upgrade manifests first (`cargo upgrade --incompatible` / `npm-check-updates`), refresh lockfiles with the vendored Rust toolchain and npm, preserve the workspace `openssl-src` path patch, then repair compile/test failures without compatibility shims.

**Tech Stack:** Vendored cargo (`setenv.sh`), cargo-edit or manual Cargo.toml edits, npm / npm-check-updates, axum/tokio stack, React+Vite WebUI.

## Global Constraints

- Scope only: `cross-compile/{onvif-rust,streaming-lib}`, `validation/rust`, `cross-compile/www` — not `.opencode` or `mock-server`.
- Always `source ./setenv.sh` and use `$CARGO` for Rust; host checks use `--target x86_64-unknown-linux-gnu`.
- Preserve `[patch.crates-io] openssl-src` path under `cross-compile/Cargo.toml`.
- No compatibility shims; fix call sites. No file deletion without user permission.
- Spec: `docs/superpowers/specs/2026-07-26-deps-bump-design.md`.

### Task 2: Bump Rust workspace manifests + lockfile

**Files:** `cross-compile/onvif-rust/Cargo.toml`, `cross-compile/streaming-lib/Cargo.toml`, `cross-compile/Cargo.lock`

- [ ] `source ./setenv.sh` from repo root.
- [ ] Ensure `cargo-edit` available (`$CARGO install cargo-edit` if needed) **or** bump versions manually from `cargo search` / crates.io.
- [ ] From `cross-compile/`: upgrade workspace members incompatibly, e.g.  
  `$CARGO upgrade --incompatible --workspace`  
  (adjust flags to cargo-edit version; do not strip path deps or the openssl patch).
- [ ] Align duplicated crate versions across `onvif-rust` and `streaming-lib` if the upgrade leaves them divergent.
- [ ] `$CARGO update` (or build that regenerates lock) so `Cargo.lock` matches.
- [ ] Confirm `cross-compile/Cargo.toml` still contains the `openssl-src` path patch.

**Verify:**  
`cd cross-compile && $CARGO check --workspace --target x86_64-unknown-linux-gnu 2>&1 | distill "PASS or FAIL; if FAIL list error crate/module lines only"`  
If FAIL, proceed to Task 4 after Task 3 (or fix immediately if trivial).
